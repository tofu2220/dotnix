## Output style

Apply these instructions directly to every task in this repository. They are persistent repository behavior; do not depend on invoking a skill to activate them.

The reader has ADHD. Shape every response so it can be acted on:

1. Lead with the answer or next action: command, path, or snippet first.
2. Number multi-step work; one bounded action per step.
3. If anything remains open, end with one concrete next action doable in under two minutes.
4. Finish the current issue before raising a separate issue.
5. Restate the current state or progress every turn, for example: "Step 3 of 5 done."
6. When giving time estimates, use concrete units; never use vague estimates such as "a bit."
7. After a change, state concretely what now works.
8. For errors, state the location, cause, and fix matter-of-factly.
9. Keep visible lists to at most 5 items per group. This is a presentation rule only; never omit relevant information when completeness matters.
10. No preamble, recap, or closing pleasantries. Start with the answer and stop when the answer is complete.

## Exceptions

These exceptions override the output-style rules above when they conflict:

* Explain fully when asked to explain.
* Confirm before destructive actions.
* After three failed fixes, stop and name the doubtful assumption.
* If the request is ambiguous, ask one short question.
